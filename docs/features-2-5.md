# ฟีเจอร์ 2–5 — 9 ตุลาคม 2026

งานนี้เพิ่มความชอบอาหาร ชุดมื้อและการคัดลอกมื้อ คำแนะนำแบบจับคู่ และประวัติน้ำหนัก/ช่วงเวลา Insights ตามที่อนุมัติ โดยไม่ได้แก้ชื่อไทย หน่วย หรือข้อมูลใน food catalog ตามข้อ 1 ที่เลื่อนไว้

## การเปิดใช้กับบัญชีจริง

หลัง migration เดิม `20261009_food_units_custom_logs.sql` ให้รัน [20261009_preferences_weights.sql](../supabase/migrations/20261009_preferences_weights.sql) ใน Supabase SQL Editor แล้วใช้ backend และ frontend รุ่นนี้ร่วมกัน

Migration เพิ่ม `food_preferences` และ `weight_logs` พร้อม RLS แยกตามเจ้าของ รันซ้ำได้ และไม่แก้ข้อมูลอาหารเดิม ส่วน `schema.sql` รวมตารางใหม่สำหรับติดตั้งใหม่แล้ว ห้ามใช้ schema ทั้งไฟล์แทน migration กับฐานข้อมูลเดิม

ยังไม่ได้รัน migration นี้บน Supabase ของผู้ใช้ หากตารางใหม่ยังไม่มี แอปจะรายงานว่าโหลดความชอบ/น้ำหนักไม่สำเร็จ โดยยังใช้การบันทึกอาหารเดิมได้ และพักคำแนะนำไว้เพื่อไม่แนะนำอาหารที่อาจเคยตั้งว่าไม่กิน โหมด Guest เก็บทุกอย่างในหน่วยความจำและหายเมื่อรีเฟรช

## วิธีใช้

- **ความชอบ:** ในหน้าเพิ่มอาหาร กด ชอบ / ไม่สนใจ / ไม่กินอาหารนี้ กดสถานะเดิมซ้ำเพื่อล้าง ค่า “ชอบ” เพิ่มคะแนนความคุ้นเคย ส่วนอีกสองค่าซ่อนจากคำแนะนำและชุดมื้อ เปิดรายการจัดการความชอบเพื่อคืนอาหารที่ซ่อนไว้ได้ การค้นหาและเลือกบันทึกเองยังทำได้ ค่า “ไม่กิน” เป็นข้อกำหนดต่อรายการอาหาร ไม่ได้วิเคราะห์ส่วนผสมหรือสารก่อภูมิแพ้
- **หลายรายการ:** เลือกอาหารแล้วกดเพิ่มในชุดมื้อ ปรับปริมาณ วันที่ และมื้อก่อนบันทึกได้ สูงสุด 30 รายการ การเขียนชุดผ่าน API เป็นคำขอฐานข้อมูลเดียว
- **คัดลอก:** ในประวัติ เลือกคัดลอกมื้อ ติ๊กเฉพาะรายการที่ต้องการ แล้วเลือกวันและมื้อปลายทาง ระบบเก็บปริมาณและโภชนาการจากบันทึกต้นฉบับ ไม่คำนวณย้อนหลังจาก catalog รุ่นใหม่
- **ชุดแนะนำ:** จับคู่สองรายการจากอาหารที่ผ่านการจัดอันดับและมีหน่วยชัดเจน ปรับปริมาณภายใน 0.5–2 เท่าของปริมาณแนะนำ และใกล้กรอบพลังงานมื้อ ยอมให้คลาดเคลื่อนจากการปัดเศษได้ 1 kcal แก้ปริมาณก่อนบันทึกได้ หากไม่มีคู่ที่เหมาะสมจะไม่เสนอชุด ไม่ได้ยืนยันว่าคู่อาหารมีสารอาหารครบทุกชนิด
- **Insights:** เลือกย้อนหลัง 7/30/90 วัน หรือกำหนดเองไม่เกิน 366 วัน รวมวันที่ไม่มีบันทึกในการคำนวณค่าเฉลี่ย บันทึกน้ำหนักได้วันละหนึ่งค่า แก้ไขวันเดิมหรือลบได้ กราฟใช้วันที่ชั่งจริง น้ำหนักใหม่ไม่เปลี่ยนเป้าหมายในโปรไฟล์อัตโนมัติ

หากบันทึกชุด/คัดลอกแล้วเครือข่ายขัดข้อง ฟอร์มจะเก็บคำขอเดิมและล็อกการแก้ไข กดลองซ้ำในฟอร์มเดิมเพื่อใช้รหัสป้องกันซ้ำ เมื่อออกจากหน้า/รีเฟรช รหัสดังกล่าวไม่คงอยู่ จึงควรตรวจประวัติก่อนเริ่มชุดใหม่

## API

ทุก endpoint ต้องเข้าสู่ระบบ และ backend ใช้สิทธิ์ของผู้ใช้กับ Supabase

| Endpoint | หน้าที่ |
| --- | --- |
| GET/PUT `/api/v1/food-preferences` | อ่าน/ตั้งความชอบ |
| DELETE `/api/v1/food-preferences/{food_key}` | ล้างความชอบ |
| POST `/api/v1/food-logs/batch` | บันทึกชุดสูงสุด 30 รายการพร้อม request_id |
| POST `/api/v1/food-logs/copy` | คัดลอกบันทึกของตนเองพร้อม request_id |
| GET/PUT `/api/v1/weight-logs` | อ่าน/บันทึกน้ำหนักตามวัน |
| DELETE `/api/v1/weight-logs/{measured_on}` | ลบน้ำหนักวันนั้น |
